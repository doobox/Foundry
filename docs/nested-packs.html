Nested packs

Ship one component, a product containing many components, or functional packs nested to any depth. The same rules apply to built-ins and third-party packs.

Acme.foundrypack/
└── Contents/
    ├── Info.plist                    type = collection
    └── Resources/
        ├── Hero.foundrypack/         type = component
        └── Navigation.foundrypack/   type = component
            └── Contents/
                └── Resources/
                    └── MenuItem.foundrypack/

Functional outer packs

The top-level pack does not have to be a collection. A component can render its own HTML and still contain more packs under Contents/Resources. A theme can do the same.

Installation behaviour

Foundry installs the selected outer bundle once. It recursively discovers valid packs without moving, renaming or flattening any child. Relative resources therefore remain stable.

Collection Info.plist

<?xml version="1.0" encoding="UTF-8"?>
<plist version="1.0">
<dict>
    <key>type</key><string>collection</string>
    <key>CFBundleIdentifier</key><string>uk.co.example.acme</string>
</dict>
</plist>
Use collection only when the pack itself has no behaviour. It describes intent; nesting does not require it.
