Bundle structure

A component uses the standard macOS bundle layout.

Example.foundrypack/
└── Contents/
    ├── Info.plist
    └── Resources/
        ├── component.html
        ├── component.css
        ├── icon.svg
        └── assets/

Contents

Info.plist identifies and configures the component.

Resources

Every HTML, CSS, JavaScript and asset file belongs under Contents/Resources. Paths declared in the plist are relative to this directory.

Nested packs

A .foundrypack may contain any number of child .foundrypack packages, and those children may contain further packs without a depth limit. Foundry installs only the selected outer package and preserves the complete directory tree. Components and themes are discovered and run directly from their nested locations; they are never flattened into the installation directory.

Collection.foundrypack/
├── Contents/
│   └── Info.plist        type = collection
├── Hero.foundrypack/     type = component
└── Navigation.foundrypack/
    ├── Contents/         type = component
    └── Menu.foundrypack/ type = component

The outer pack may itself be a functional component or theme, or it may use collection when it exists only to group child packs.

icon.svg

Type: SVG fileRequired

Every component must provide a square SVG named exactly icon.svg directly inside Contents/Resources. Foundry uses it in the Components panel and component identity UI. The filename is convention-based and is not declared in Info.plist.

Foundry discovers icon.svg by convention. Templates and other assets must still be explicitly declared.
