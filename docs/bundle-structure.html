Packages

Pack structure

A .foundrypack is a standard macOS-style bundle. Foundry keeps it intact and runs its components directly from their packaged locations.

Example.foundrypack/
└── Contents/
    ├── Info.plist
    └── Resources/
        ├── component.html
        ├── component.css
        ├── editor.css
        ├── component.js
        ├── icon.svg
        └── assets/

What goes where

Contents/Info.plist
Identity, templates, inspector controls and slots.
Contents/Resources
All templates, assets and nested .foundrypack bundles. Paths declared in Info.plist are relative to this directory.
icon.svg
A square component icon placed directly in Resources. Foundry discovers this filename by convention.

Pack types

component
A functional component that produces markup and may also contain child packs.
theme
A functional theme pack that may also contain child packs.
collection
A non-functional outer pack used only to group child packs.
No extraction step. Installing an outer pack preserves its complete tree. Nested components continue to run from inside it.

Declared resources

Text templates—including HTML, CSS, JavaScript, Sass, SCSS and PHP—are named under templates. Other exportable files are listed under assets. This makes package contents explicit and validation predictable.

Nested packs
