Useful controls, already designed

A smart control is a preconfigured customItems control for a common web concept. Foundry supplies the right editor, choices, symbols, validation and template value; the component developer supplies the ID and decides where the value is used.

The same custom-item model

Smart controls do not introduce a second plist collection. They live in customItems, store one developer-named value and resolve through the usual template macro.

<dict>
    <key>id</key><string>alignment</string>
    <key>title</key><string>Alignment</string>
    <key>group</key><string>Typography</string>
    <key>control</key>
    <dict>
        <key>type</key><string>textAlignment</string>
    </dict>
    <key>default</key><string>start</string>
    <key>responsive</key><true/>
</dict>
#{{ id }} {
    text-align: {{ control.alignment }};
}

For textAlignment, Foundry provides a segmented control with the correct alignment symbols, portable choices and validated CSS output. The developer does not need to rebuild that option list for every component.

What makes a control smart?

Purpose-built UI
Segmented symbols, specialised pickers, previews, unit handling or other interaction appropriate to the value.
Known semantics
Foundry understands the value well enough to validate it and present sensible defaults.
Stable output
The control resolves to a documented CSS-safe value through {{ control.<id> }}.
Optional theme data
Where relevant, themeValues adds compatible project-theme choices alongside custom values.
Responsive support
The same control can inherit and override values at Foundry breakpoints.

Good candidates

Typography
Font weight, line height, letter spacing, text decoration, text transform and whitespace.
Layout
Display, flex/grid alignment, gap, sizing, overflow and aspect ratio.
Appearance
Border style, corner radius, shadow, opacity and blend mode.
Media
Object fit, object position, loading behaviour and aspect ratio.
Links and behaviour
Link target, relationship, cursor and visibility.
Accessibility
Landmark role, labels and appropriate ARIA choices where a component genuinely needs them.
Smart does not mean generated CSS. Foundry provides the value and editor; the component’s own templates still determine the target element and declaration.
