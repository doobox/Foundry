Built-ins required before shipping

The smallest complete component library needed to build a real, responsive website without immediately depending on a third-party pack.

Internal checklist. This page is temporary and is not part of the public component API. “Required” means launch-blocking; specialist and decorative components belong in later packs.

Already built

✓ Container

General-purpose structure with child components, width, spacing and alignment.

Controls expected: number, select, toggle, responsive values and smart text alignment.

✓ Paragraph

Editable body copy with typography and colour controls.

Controls expected: editable text, smart font family, smart font size, smart text alignment and colour.

Content and actions

Heading

Editable heading text with semantic levels h1–h6, visual size independent of level, alignment, type and colour.

Controls expected: editable text, select, smart font family, smart font size, smart text alignment and colour.

Image First pass built

The responsive %image% primitive, dedicated drop zone, project-asset drop and Finder import are implemented. Controls remain for the shipping pass.

Controls expected: image asset picker, text, toggle, link/page destination, responsive dimensions, select and focal-point picker.

Button

Editable label, internal or external destination, semantic link/button behaviour, target, accessible label, alignment and common visual styles.

Controls expected: editable text, link/page destination, select, toggle, smart text alignment, colour, responsive spacing and border controls.

Link

An inline text link for places where a full button is inappropriate. It must support internal pages, external URLs, email and telephone destinations.

Controls expected: editable text, unified link destination, toggle and text for an accessible label.

List

Editable ordered and unordered lists with add, remove and reorder support. List items should remain semantic rather than simulated paragraphs.

Controls expected: reorderable item collection, editable text, select, smart typography, colour and responsive spacing.

Layout

Columns

A responsive row with reorderable child regions, per-breakpoint column counts or widths, gap, alignment and stacking order.

Controls expected: repeatable named slots, responsive number/dimension values, gap, alignment, distribution and stacking-order controls.

Grid

A repeatable responsive grid for cards and other sibling content, with minimum item width, column count, gap and alignment.

Controls expected: child slot, responsive number/dimension values, gap, alignment and auto-fit/column-mode select.

Spacer

Intentional responsive vertical space. It avoids authors using empty paragraphs or component-specific margin tricks.

Controls expected: responsive dimension with unit and sensible minimum/maximum constraints.

Divider

A semantic horizontal rule with responsive width, thickness, colour and spacing.

Controls expected: responsive dimensions, colour, select for line style and smart alignment.

Navigation and site structure

Navigation

Builds links from the project page tree, supports nested pages, current-page state, responsive collapse and accessible keyboard operation.

Controls expected: page-tree picker, breakpoint, select, toggle, smart alignment, colour, typography, responsive spacing and icon picker.

Site Logo

Theme/site identity image or text with an accessible home-page link and responsive sizing.

Controls expected: image asset picker, text, mode select, responsive dimensions and home-page destination.

Breadcrumbs

Semantic navigation derived from page ancestry, including the appropriate structured-data markup.

Controls expected: page-tree context, text, separator/icon picker, toggle, smart typography, colour and responsive spacing.

Media

Video

Local video and privacy-conscious external embeds, with poster, controls, captions, aspect ratio and autoplay safeguards.

Controls expected: media asset picker, URL, image asset picker, caption-track picker, aspect ratio, toggle and responsive dimensions.

Icon

An accessible project icon with size, colour and decorative/labelled modes. It must be usable alone or inside other components.

Controls expected: icon picker, responsive dimension, colour, toggle and text for an accessible label.

Forms

A form is only useful when its controls share validation, naming and submission behaviour. These should be designed and tested as one built-in family.

Form

A child-component container defining method, action, success/error behaviour and shared validation semantics.

Controls expected: child slot restricted to form controls, select, URL/action destination, success-page picker, toggle and editable status messages.

Text Field

Label, name, input type, autocomplete, placeholder, required state, help text and validation message.

Controls expected: text, input-type select, autocomplete select, toggle, validation rules and smart typography/colour controls.

Text Area

Multiline input with the same accessible label, help, required and validation contract as Text Field.

Controls expected: text, number for rows, toggle, validation rules and smart typography/colour controls.

Select

Editable options, label, name, required state and a genuine native select element by default.

Controls expected: text, reorderable label/value option collection, toggle, validation rules and smart typography/colour controls.

Checkbox

A single agreement control and grouped choices, with correct labels, values and required behaviour.

Controls expected: text, reorderable label/value option collection, toggle, validation rules, colour and responsive spacing.

Submit Button

A form-aware action with editable label and disabled/submitting states.

Controls expected: editable text, smart alignment, colour, responsive spacing, border controls and editable submitting label.

Escape hatch

HTML / Embed

A clearly labelled advanced component for custom HTML and trusted embed code. Canvas isolation and export behaviour must be explicit.

Controls expected: multiline code editor, language/mode select, trusted-code warning acknowledgement and canvas-preview toggle.

Definition of done

  • Uses semantic, accessible markup without JavaScript where native HTML is sufficient.
  • Works at every Foundry breakpoint and does not assume the top-level selector.
  • Supports keyboard use, sensible focus states and reduced-motion preferences where relevant.
  • Exports only the CSS and JavaScript it needs and behaves correctly with multiple instances.
  • Has an icon, useful defaults, inspector help, automated rendering tests and developer-facing source files in the built-ins pack.
